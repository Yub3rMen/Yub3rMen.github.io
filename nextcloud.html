01 / The objective

Useful infrastructure, not just a simulation.

I wanted an alternative to relying entirely on third-party cloud storage for family file access and smartphone photos. The goal was to operate the service myself while learning how a real application depends on the operating system, containers, storage, networking, and client devices.

What makes this project different from a one-time lab is ongoing use: I've added users, helped people connect new phones, tested file and photo uploads, and returned to troubleshoot issues that appeared after deployment.

This is a personal learning environment, built and maintained with step-by-step guidance. It is not presented as an independently engineered enterprise deployment.

03 / Hands-on responsibilities

What I worked on

Application hosting

Installed and managed a self-hosted application on Ubuntu using Docker. Used container administration tools to investigate service state and support updates.

02 / NETWORK ACCESS

Private connectivity

05 / What the project shows

Skills that translate to IT support and infrastructure roles.

Running a service people depend on means that connectivity, authentication, storage, and updates all matter. This project made me practice troubleshooting across those boundaries, rather than treating each technology in isolation.

Areas of hands-on exposure include Linux administration, containerized application hosting, private networking, endpoint troubleshooting, user management, and technical documentation.

Next steps: verify the exact application data path, document the container layout, audit network exposure and authentication settings, and perform a separate tested backup-and-restore procedure for Nextcloud data.
